# Консьерж — ИИ-агент поддержки в Telegram

Отвечает клиентам по базе знаний (RAG) **со ссылкой на источник**, передаёт сложные вопросы сотруднику, а любое действие (возврат, проверка платежа) выполняется только после **подтверждения сотрудником кнопкой**. Каждый шаг пишется в журнал (JSONL).

## Проблема
Малый бизнес теряет обращения: оператор ищет ответ в нескольких местах, а ИИ-бот без контроля может пообещать лишнее. Консьерж отвечает только по базе и не действует без человека.

## Как работает
```
Клиент ──► Telegram-бот ──► RAG по kb/*.md (BM25) ──► ответ + источник
                 │                     │ нет ответа / нужно действие
                 │                     ▼
                 │           заявка в чат операторов [✅ Подтвердить] [❌ Отклонить]
                 │                     │
                 ◄──── результат ◄─────┘
       все события ──► data/journal.jsonl
```
- `concierge/rag.py` — индекс по markdown-папке `kb/`, без внешних зависимостей.
- `concierge/agent.py` — логика: ответ, эскалация, решение оператора; опционально LLM через любой OpenAI-совместимый API (если не задан — отдаётся цитата из базы; при ошибке API — тоже).
- `concierge/bot.py` — aiogram 3, inline-кнопки подтверждения.
- `concierge/journal.py` — журнал действий.
- `kb/` — пример базы знаний вымышленной компании «Пример-Маркет».

## Запуск за 5 минут
```bash
python3 -m concierge --demo            # без токена и сети, только stdlib
python3 -m unittest -v tests.test_agent

python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env                   # BOT_TOKEN, OPERATOR_CHAT_ID
set -a; . ./.env; set +a; python -m concierge.bot
```
Свою базу знаний — просто положить `.md` файлы в `kb/`.

## Ограничения
- Поиск лексический (BM25 с грубым стеммингом), без эмбеддингов; для большой базы стоит заменить на FAISS/sqlite-vec.
- Заявки хранятся в памяти процесса: после перезапуска неподтверждённые теряются (журнал сохраняется).
- Нет интеграции с CRM/заказами — действие после подтверждения пока только фиксируется в журнале.
- Один чат операторов, без ролей и прав.

## English summary
**Concierge** is a Telegram support agent: answers from a markdown knowledge base with source citations, escalates unknown or action-requiring questions to staff, and executes actions only after a staff member presses a confirm button. Every event is logged to JSONL.
Quick start: `python3 -m concierge --demo` (no token, stdlib only); real bot: `pip install -r requirements.txt`, fill `.env` from `.env.example`, `python -m concierge.bot`.
Limitations: lexical BM25 retrieval, in-memory tickets, no CRM integration yet.
